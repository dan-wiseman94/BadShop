# Playful creation and community reuse

Baseline: clean `7d64ef862d316a0cacd9d7b1723985eed7d36dc6`; origin/main fetched at task start.
The user authorized implementation of the market-fit recommendations, prioritizing
wide open-source adoption, fun and impact. This plan does not claim customer evidence.

## Delivery slices and acceptance

1. Personal previews: importing/selecting a picture updates six deterministic idea
   thumbnails without appending steps or artifacts. Choosing a format creates an
   ordinary editable layout. Late previews cannot replace a newer picture's previews.
2. Cast: name a character, expression and collection using the persistent asset library;
   use it in another project, rename/remove it, and share a collection through existing
   packs. Removal does not remove images already used in projects.
3. Visual recipes: capture a completed step, edit its ordinary schema-based controls,
   name/save it and run it on selected pictures without JSON. Existing version-1 recipes
   remain readable; preserve multi-image slots. Cancel keeps completed outputs.
4. Remix: preview selected dependency assets and export an editable `.badshop` copy.
   Exclude conversations, provider IDs, unrelated branches/images, original files and
   private filenames. Keep selected pixels, captions and public source credits. Opening
   uses the existing save/discard guard. Export never overwrites another file.
5. Directed surprise and reaction sets: authored collections provide coherent alternate
   formats and six editable reactions. Keep explicit source/wording choices; render via
   the session. Cancellation keeps completed work; no provider/download required.
6. Creation replay: select 2–12 visible results and create a bounded GIF with existing
   animation tools; retain a normal replayable step and ordinary export controls.
7. Local challenge: choose a prompt and create named round branches on one computer,
   reveal/compare results, save/reopen and continue. No account, network lobby or telemetry.
8. Distribution and participation: improve first-run progressive disclosure, document
   import boundaries, supply launch/contribution/pack-authoring material and an opt-in
   four-week study kit. Add phone-photo decoding where dependency/package checks support it.

Existing owners: session execution/previews, AssetLibrary, declarative Recipe, project
archive validation, branches, registered layouts/animation and QuickStart. No second
pixel engine, account system, cloud gallery or arbitrary-code pack format.

Keep each observable feature in a separate commit/review slice. Run its focused core
regression and real browser/core journey, then relevant maintenance checks. Preserve
evidence under artifacts/verification. Obtain an independent final diff review using
docs/diff-review.md. External recruitment, signing identities and publication outcomes
must be reported honestly; do not substitute plans for completed studies or signed builds.
