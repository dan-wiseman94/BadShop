# badshop implementation roadmap

**Spec:** `docs/superpowers/specs/2026-09-26-badshop-app-design.md`

The spec spans seven milestones across independent subsystems, so it is built as seven
plans. Each produces working, tested software on its own and hands a stable interface to
the next. Plans 1 and 2 established the core. The remaining implementation is tracked in
[`2026-10-31-complete-app.md`](2026-10-31-complete-app.md), with validation and release gates
recorded separately from implementation completion.

| # | Plan | Spec milestone | Produces (the interface later plans consume) | Status |
|---|---|---|---|---|
| 1 | **Core engine, tool registry, CLI** | §13.1 | `badshop` Python package: `engine/*` pure functions; `tools.registry.REGISTRY` of `ToolSpec`s with Pydantic params and JSON schemas; `tools.runner.run_tool(name, raw, store)`; the `Store` protocol; `badshop` CLI with parity to the reference (all 23 commands) | done 2026-09-27: `2026-09-26-plan-1-core-engine.md`; rulings in `2026-09-27-plan-1-rulings.md`, deferred items in `2026-09-27-plan-1-carry-forward.md` |
| 2 | **Sessions and local server** | §13.2 | `session/` (artifacts by SHA-256, steps, replay with remapping and cache, `.badshop` project files, autosave) as a `Store`; `server/` WebSocket JSON-RPC API and events (spec §7); scripted fake provider; headless agent loop skeleton | done: `2026-09-27-plan-2-sessions-server.md`; what Plan 3 and later inherit is in `2026-09-27-plan-1-carry-forward.md` |
| 3 | LiteLLM provider and agent | §13.3 | `providers/litellm_provider`, provider profiles, keyring secrets, capability checks, image budgeting, approval gate, system prompt from `reference/SKILL.md`; `badshop chat` terminal client | implemented: native/JSON tool providers, vision context, terminal client; live cloud and local vision/tool smoke passed |
| 4 | Desktop shell MVP | §13.4 | `app/` Tauri 2 + React/TS: chat, viewer, steps timeline, edit and replay, tool palette with generated forms, approvals, settings, sessions, first run | implemented in `2026-10-31-complete-app.md`; see its validation record |
| 5 | MCP proxy and CLI agents | §13.5 | `mcp/` proxy (MCP SDK v2), `providers/cli_provider` for Claude Code, then Codex, then Gemini (experimental); starts with the unverified-detail spikes listed in spec §14 | implemented in `2026-10-31-complete-app.md`; see its validation record |
| 6 | Packaging and release CI | §13.6 | PyInstaller onedir core, Tauri bundles (AppImage, deb, NSIS, dmg), Flatpak manifest, per-OS smoke tests, GitHub Release workflow, PyPI publish; packaged CLI skill under `skills/badshop` | implemented in `2026-10-31-complete-app.md`; see its validation record |
| 7 | Release polish | §13.7 | error screens, diagnostics, README with screenshots, licence and attribution notices | implemented in `2026-10-31-complete-app.md`; see its validation record |

Order is strict: each plan depends on the interfaces of the ones before it. Plans 3 and 4
could overlap once Plan 2's API is frozen, if two people are working.
