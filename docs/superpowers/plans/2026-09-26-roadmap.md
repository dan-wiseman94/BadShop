# badshop implementation roadmap

**Spec:** `docs/superpowers/specs/2026-09-26-badshop-app-design.md`

The spec spans seven milestones across independent subsystems, so it is built as seven
plans. Each produces working, tested software on its own and hands a stable interface to
the next. Only Plan 1 is written in full now; each later plan is written when its turn comes,
against the code that actually exists by then (using superpowers:writing-plans).

| # | Plan | Spec milestone | Produces (the interface later plans consume) | Status |
|---|---|---|---|---|
| 1 | **Core engine, tool registry, CLI** | §13.1 | `badshop` Python package: `engine/*` pure functions; `tools.registry.REGISTRY` of `ToolSpec`s with Pydantic params and JSON schemas; `tools.runner.run_tool(name, raw, store)`; the `Store` protocol; `badshop` CLI with parity to the reference (all 23 commands) | written: `2026-09-26-plan-1-core-engine.md` |
| 2 | Sessions and local server | §13.2 | `session/` (artifacts by SHA-256, steps, replay with remapping and cache, `.badshop` project files, autosave) as a `Store`; `server/` WebSocket JSON-RPC API and events (spec §7); scripted fake provider; headless agent loop skeleton | not yet written |
| 3 | LiteLLM provider and agent | §13.3 | `providers/litellm_provider`, provider profiles, keyring secrets, capability checks, image budgeting, approval gate, system prompt from `reference/SKILL.md`; `badshop chat` terminal client | not yet written |
| 4 | Desktop shell MVP | §13.4 | `app/` Tauri 2 + React/TS: chat, viewer, steps timeline, edit and replay, tool palette with generated forms, approvals, settings, sessions, first run | not yet written |
| 5 | MCP proxy and CLI agents | §13.5 | `mcp/` proxy (MCP SDK v2), `providers/cli_provider` for Claude Code, then Codex, then Gemini (experimental); starts with the unverified-detail spikes listed in spec §14 | not yet written |
| 6 | Packaging and release CI | §13.6 | PyInstaller onedir core, Tauri bundles (AppImage, deb, NSIS, dmg), Flatpak manifest, per-OS smoke tests, GitHub Release workflow, PyPI publish; switch the Claude Code skill to the published `badshop` CLI | not yet written |
| 7 | Release polish | §13.7 | error screens, diagnostics, README with screenshots, licence and attribution notices | not yet written |

Order is strict: each plan depends on the interfaces of the ones before it. Plans 3 and 4
could overlap once Plan 2's API is frozen, if two people are working.
